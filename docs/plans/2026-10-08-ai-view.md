# Plano: Visão IA das páginas

> **Spec:** `docs/specs/ai-view/SPEC.md`
> **Slug:** `ai-view` · **Criado:** 2026-10-08
> **Profundidade:** Deep (13 requisitos) · **Tarefas:** 10 · commit por tarefa

**Objetivo:** toda página coberta ganha um switcher Humano | IA, uma visão `<página>/ia`
renderizada no servidor e uma versão `<página>.md`, sem script novo no navegador além do
Copiar dentro do script único.

**Arquitetura:** `src/lib/ai-view/` concentra os builders de markdown por página, o registro
`markdownForPath(path)` (a única tabela caminho → markdown), o renderizador (`marked`, só
servidor) e o mapa de rótulos. Duas rotas genéricas SSR, `src/pages/[...path].md.ts` e
`src/pages/[...path]/ia.astro`, consultam o registro e devolvem 404 quando ele não conhece o
caminho. O switcher entra no `BaseLayout`. O Copiar vai para o script do `PointerField`.

**Stack:** Astro 7 SSR, `marked` 18.1.0, Vitest + `experimental_AstroContainer`.

## Fatos verificados

| Fato | Evidência |
|---|---|
| Rotas genéricas resolvem `/ia`, `/sobre/ia`, `/<post>/ia`, `/lab/forja/ia`, `/posts/arquivo/2017/ia` e os `.md` correspondentes; as rotas `.md` explícitas de case têm prioridade | sonda HTTP contra o build, 2026-10-08 |
| Caminho desconhecido cai na rota genérica com 200 | sonda: `/nao-existe/ia` → 200; a rota precisa devolver 404 |
| Corpo cru do post | `getPostEntry(slug)` → `entry.body` (`src/lib/content/posts.ts`) |
| Markdown de case | `buildCaseMarkdown` (`src/lib/aeo/case-markdown.ts`) |
| Script único: 473 B gzip de 1.536 B | medido no build |

### Task 2: builders de markdown por página

**Requirement:** REQ-003, REQ-004 · **Files:** Create `src/lib/ai-view/pages.ts`; Test `tests/ai-view/pages.test.ts`
**Team:** backend · `backend-engineer` · reviewers business-logic-reviewer, test-reviewer

Funções puras, uma por página, todas devolvendo markdown em pt-BR (o conteúdo das páginas
humanas) e começando por frontmatter `title`, `url`:
- `homeMarkdown({ site, profile, portfolio, lab })`: headline, posicionamento, disponibilidade, até 5 cases por coleção com link, serviços.
- `aboutMarkdown({ site, profile })`: headline, bio, resultados (valor, rótulo, contexto), frentes com link do case, experiência (período, cargo, empresa, resumo, destaques), formação, stack.
- `collectionMarkdown({ site, collection, title, description, projects })`: uma entrada por case com resumo, stack, situação e link `.md`.
- `postsMarkdown`, `archiveMarkdown`, `archiveYearMarkdown`: listas com data, título, resumo e link.
- `contactMarkdown({ site, profile })`: contato direto sem e-mail cru? **Não**: a página humana mostra o e-mail, mas o `.md` é superfície de máquina e passa pelo portão de vazamento, então lista GitHub e LinkedIn e aponta `POST /api/hire` e `/conectar`.
- `connectMarkdown({ site })`: endpoint MCP, passos por cliente, tools do `MCP_TOOLS` com descrição, `/api/hire`.
- Testes por builder com fixtures; nenhum builder lê `clientName` ou `confidentialMetrics`.
